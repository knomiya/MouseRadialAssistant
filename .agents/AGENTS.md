# 项目专属规范与行为准则

## 1. README.md 编写规范 (严格执行)
- **仅书写标准功能特性**：`README.md` 作为开源/公开项目的官方产品文档，必须只使用专业、正规、高大上的产品语言介绍**功能本身 (Features)**。
- **严禁包含排错细节与调试背景**：严禁将开发测试过程中的排错背景、特定第三方软件名称（如“微信/PixPin截图”、“Wallpaper Engine动态壁纸”等）、漏洞/Bug修复历史、或“绝不伪造数据”等调试补丁语汇写入 `README.md`。

## 2. 版本号与发版规范 (严格执行)
- **严禁擅自递增版本号与发版**：在用户没有给出明确的“发版/更新版本号”指令之前，AI 助手**绝对不能擅自递增版本号**（如从 v0.1.2 自动变更至 v0.1.3 等）。
- **打包与配置版本一致性**：所有本地修改及便携包的压缩文件包名，必须严格与当前项目 confirmed 的版本号完全一致。
